# 04 — QA

## Objective

Complete reproducible container setup and verify the highest-risk authorization and end-to-end flows.

## Scope and relevant files

- `api/Dockerfile`, `web/Dockerfile`, and `compose.yaml`
- Required API authorization tests
- Focused fixes in `api/**` or `web/**`
- Manual verification evidence

Keep infrastructure, tests, and discovered fixes in separate atomic commits.

## Dependencies

- Tasks 01–03 accepted
- Parent and Child flows available

## Acceptance criteria

- The three required authorization test cases in the plan pass.
- The complete manual verification checklist passes or has documented blockers.
- A clean Docker Compose build starts PostgreSQL, migrates/seeds the database, and serves both applications.
- No password hashes, cross-child data, or unauthorized mutations are exposed.

## Verification commands

```text
npm run lint --prefix api
npm run build --prefix api
npm test --prefix api
npm run lint --prefix web
npm run build --prefix web
docker compose config
docker compose up --build -d
```

Run the manual checklist against the running stack, then use `docker compose down`.

## Expected handoff

Provide commits, automated results, manual checklist results, container startup evidence, defects fixed, and unresolved release risks.
